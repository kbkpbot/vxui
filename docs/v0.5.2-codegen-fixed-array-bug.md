# V 0.5.2 codegen bug: fixed-size array field assigned from a converted
# nested-array literal produces invalid C

**Environment:** V 0.5.2 (commit 9142d68), Linux x86_64, gcc backend.
Reproduces identically in debug and `-prod` builds; tcc fails first, then the
cc fallback fails on the same broken C.

**Discovered while writing unit tests for `examples/game-2048` (rules_test.v).**

---

## Trigger (minimal repro — see `bug_repro.v` alongside this file)

ALL of the following together:

1. a struct field of fixed-size nested-array type, e.g. `cells [4][4]int`
2. an assignment `struct.field = f([...nested literal...])` where
3. `f` takes `[][]int` and returns `[4][4]int` (i.e. the call site performs an
   implicit nested-array-literal -> fixed-size-array conversion)

```v
struct Board {
mut:
	cells [4][4]int
}

fn board_of(vals [][]int) [4][4]int {
	mut b := [4][4]int{}
	for r in 0 .. 4 {
		for c in 0 .. 4 {
			b[r][c] = vals[r][c]
		}
	}
	return b
}

fn main() {
	mut bd := Board{}
	bd.cells = board_of([   // <- generates invalid C
		[0, 0, 0, 2],
		[0, 0, 0, 0],
		[0, 2, 0, 0],
		[0, 0, 0, 0],
	])
	println(bd.cells[0][3])
}
```

## Observed C error

```
cc: .../repro3.*.tmp.c: In function 'main__main':
cc: error: expected expression before 'volatile'
cc:  5114 |  memcpy(bd.cells, volatile Array_int _t2 =
cc:       |     builtin__new_array_from_c_array_noscan(4, 4, sizeof(int),
cc:       |     _MOV((int[4]){0, 0, 0, 2}));
cc: error: too few arguments to function 'memcpy'
```

The generated C puts a **`volatile Array_int _t2 = ...` variable declaration
inside the argument list of `memcpy`** — a statement/expression confusion in
the C generator while materialising the literal-to-fixed-array conversion.

## Boundary matrix (all measured, see `workaround_ok.v`)

| Scenario | Compiles? |
|---|---|
| literal stored in a named variable first, then `field = f(v)` | ✅ OK |
| 1-D: `field [4]int` assigned from `f([9,8,7,6])` | ✅ OK |
| same expression assigned to a **local** fixed array (not a struct field) | ✅ OK |
| **literal passed inline to `f`, result assigned to struct field** | ❌ broken |
| `-prod` build of the broken case | ❌ broken (same C error) |

## Workaround

Do not assign the call result directly to the struct field. Either

```v
v := [[0, 0, 0, 2], ...]        // named literal first
bd.cells = board_of(v)
```

or fill the field element-wise (what `examples/game-2048/rules_test.v` does
via `set_board`):

```v
fn set_board(mut app App, vals [][]int) {
	for r in 0 .. 4 {
		for c in 0 .. 4 {
			app.board[r][c] = vals[r][c]
		}
	}
}
```
